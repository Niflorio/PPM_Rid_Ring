# Работа с Codex

Codex — исполнитель отдельных исследовательских задач и редактор документов, **не источник фактов сам по себе**.

## Процесс
1. Создать GitHub Issue с целью, входными материалами и критериями приёмки.
2. Выделить рабочую ветку.
3. Поручить Codex **один ограниченный пакет изменений** (например, только `03_Продуктовая/Конкуренты.md`).
4. Требовать URL + дату для каждого внешнего факта, ссылку на страницу PDF для каждого утверждения о патенте.
5. Просмотреть `git diff`, проверить источники вручную, сделать PR и review.

## Пример задания
> Проанализируй `03_Продуктовая/Конкуренты.md` и предложи обновления только в этом файле. Не меняй другие документы. Сохрани разделение на факты патента, проверенные внешние данные и гипотезы. Для каждой актуальной характеристики конкурента приведи первичный URL и дату проверки. Не придумывай технические характеристики, цены и результаты тестов. В конце перечисли открытые вопросы. Не создавай PR без согласования.

## Ограничения данных
До разрешения правообладателя не выкладывать непубличные схемы, переписку, результаты испытаний и договорные документы в облачные сервисы/репозитории. Патентный PDF публичен, но сам факт публикации патента не даёт прав на непубличные материалы автора.

Не расходовать сессию Codex на бессмысленные циклы автоисправлений: заранее ограничивать объём, просить сначала план и diff.
